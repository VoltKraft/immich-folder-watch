# Synthetic FAT16 data image

Development fixture only. Neither this image nor its formatter belongs in an
application package. Windows consumes the checked-in 15,409-byte compressed
template with Python's standard library; it downloads or installs nothing.

The empty filesystem is generated by **dosfstools 4.2**, licensed
**GPL-3.0-or-later**, compatible with this repository's AGPL-3.0-only work.
The complete original source archive and unmodified COPYING are retained here.
The archive has 151 regular files, no links and no image/font assets.
Its original copyright notices and build-tool exceptions remain intact.

Authoritative release: <https://github.com/dosfstools/dosfstools/releases/tag/v4.2>.
Archive SHA-256:
`64926eebf90092dca21b14259a5301b7b98e7b1943e8a201c7d726084809b527`.
The relevant generator is `src/mkfs.fat.c`; its copyright holders include Linus
Torvalds, Remy Card, David Hudson, H. Peter Anvin, Roman Hodek, Daniel Baumann,
Andreas Bombe and Pali Rohár. See [COPYING.dosfstools](COPYING.dosfstools).

The recipe removes bytes 62 through 509, all 448 bytes of the generated x86
boot program and message. It keeps the ordinary jump/BPB and empty FAT metadata.
The enclosing MBR contains no bootstrap program and has no active partition.
This is a data volume, not boot media. There are no user files or credentials.

To reconstruct on an isolated Linux development host with a C compiler and
Make, extract the exact source archive into a fresh directory beneath
`artifacts/rust/storage-faults`, run `CC=/usr/bin/gcc ./configure`, then `make -j2`
without installation. From the repository root, run:

```sh
python3 tools/rust-qa/storage-faults/make_windows_template.py \
  --source-archive tools/rust-qa/storage-faults/windows-image/dosfstools-4.2.tar.gz \
  --mkfs artifacts/rust/storage-faults/windows-design-reference/dosfstools-4.2/src/mkfs.fat \
  --fsck /usr/sbin/fsck.fat \
  --output artifacts/rust/storage-faults/windows-template-new
```

Compare its `fat16.img.zlib`, `template.json` and COPYING with these checked-in
files. The independent `fsck.fat -n -v` check must pass after boot-code removal.
`generation.json` records the exact commands, original filesystem and actual
generator/checker executable hashes. The source-built upstream generator and
the installed Fedora 4.2-19.fc45 generator independently produced identical
template bytes in the recorded local runs; native Windows mounting remains a
separate check. No Linux device or mount is used by this recipe.

The VHD wrapper is first-party code implementing the fixed format in Microsoft's
[VHD specification](https://www.microsoft.com/en-us/download/details.aspx?id=23850),
which declares the Microsoft Open Specification Promise. No Microsoft document
or example program is redistributed. The firmware-scoped Microsoft FAT document
was not used to implement a new formatter. FAT bytes come from the source-pinned
GPL tool above.

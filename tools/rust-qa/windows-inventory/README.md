# Windows inventory workload

The paired Windows recorder stages the reviewed Rust GUI beside a native inventory worker on a disposable GitHub-hosted Windows x64 or ARM64 machine. The development workload reads one synthetic YAML configuration, verifies its owner token beneath `RUNNER_TEMP`, opens the configured directory by handle, and fingerprints each permitted JPEG by size and modification time. It makes two initial inventories and continues on the existing five-second reconciliation interval until the supervisor closes its pipe. The endpoint is an exclusively reserved local loopback port. There are no uploads. [Shared read-only inventory](../performance/worker/src/main.rs) · [Windows handle operations](../../../rust/crates/safe-fs/src/windows.rs)

The builder verifies the original Cargo manifest, lock and worker source checksum. It adapts configuration acquisition, the offline port and the startup barrier in an isolated build tree. All registry inputs come from the YAML assessment's checksum-bound filtered archive. Cargo resolves only previously reviewed packages and features on the native target, then runs frozen Clippy and a release build. The build receipt binds the compiled entry, source files, actual executables, ETW observer and dependency selection. The GUI starts its worker with a private inherited pipe. In regular desktop assessments the worker is disabled. [Staging and source checks](subject.py) · [Windows profile adapter](windows_profile.rs)

The paired fixture contains 100 directories with 1,000 distinct empty JPEGs each. WPF and Rust start with fresh state in separate process jobs. The driver verifies the originally issued random marker before launch. It resumes the suspended WPF process only after its PID-filtered ETW session is ready. The Rust worker waits on its supervisor's pipe until its own session is ready. All measurements use the synthetic NTFS fixture. [Driver](scan.py) · [Windows job and ETW cleanup](../windows-performance/native.py)

The observer correlates kernel file events by target PID, I/O request packet, kernel file object and QPC. Every directory requires a successful directory open, a query returning data and the end-of-directory status from its own handle. That read establishes the pass number for that directory. Both native implementations enumerate the directory before fingerprinting its files. Each regular-file fingerprint requires a successful open with `FILE_NON_DIRECTORY_FILE`. Enumeration's preliminary attribute opens have different options. In WPF, the regular-file lease, the length getter and the last-write getter each call the NTFS identity query. The observer requires three successful `FileIdInformation` completions on the same file object. Rust requires the successful identity query and exact, ordered worker snapshots of 100,000 files with 100,000 then zero changes. The WPF log gives the observation deadline for each pass. Its `queued 0` count alone contains no fingerprint evidence. [WPF reconciliation](../../../src/ImmichFolderWatch.Core/Services/FolderWatchWorker.cs) · [WPF metadata operations](../../../src/ImmichFolderWatch.Core/Services/SecureFileSystem/SecureNativeFileSystem.Windows.cs) · [WPF size and modification time](../../../src/ImmichFolderWatch.Core/Services/SecureFileSystem/SecureWatchFile.cs) · [Rust filesystem operations](../../../rust/crates/safe-fs/src/windows.rs)

The Windows SDK's installed manifest supplies the layout of create, cleanup/close, directory enumeration, metadata query and operation-end events. Each of the two ordered passes must cover all 100 directory handles and 100,000 distinct successful fingerprint leases. Missing or ambiguous operations, failed statuses, duplicate paths, event loss or overlapping passes invalidate the measurement. The second pass cannot fill gaps in the first. If the host omits the required NTFS telemetry, the result remains unqualified and needs a separate validated observation. The PID-bound trace is capped at 3 GiB and its hash and size are recorded on successful validation. After decoding, the driver verifies removal of its own ETW session and deletes the raw trace from the temporary directory. [Provider events](https://github.com/microsoft/Tx/blob/master/Generated/Microsoft_Windows_Kernel_File.cs) · [NT information classes](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/content/ntifs/nf-ntifs-ntqueryinformationfile) · [Native decoder](file-observer.cpp)

Each of three trials requires the original live inventory PID and independent HWND show/hide events. At least five requests per direction must start and finish within the first pass, with bracketing file activity within half a second. The ledger retains the first and last QPCs of each group of at most 32 distinct successes. Idle CPU and working set include the whole subject tree. The driver fixes the same-host WPF budget before running Rust. [Scan recorder](scan.py) · [Predeclared comparison](../windows-performance/metrics.py)

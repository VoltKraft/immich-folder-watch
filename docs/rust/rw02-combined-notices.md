## Reading an archive

Open `NOTICE.txt` for the package names, compiler roles, file paths and
five individual Noto font attributions. In `manifest.json`, `compiledFor`
lists `host`, the native target triple or both. `files` gives the byte length
and SHA-256 of each payload, including `NOTICE.txt`. The manifest records
the native archive, receipt, source inventory, compiler units and executable
digests. Each registry package has its upstream archive URL and digest. The
three reconstructed packages also identify their reviewed source trees.

- `crates/NAME-VERSION/` preserves source paths and exact file bytes. For
  example, the four relative links in granit-parser's `LICENSE` resolve to
  the original inherited grants. The ring notices retain their nested paths.
  The base64 crate contributes its two license files.
- `repository/` preserves Git paths at the native revision. The six project
  packages point to the project AGPL-3.0-only license. Packages with
  supplemental or reconstructed notice inputs reference the reviewed originals
  here. Each font record identifies the original asset by URL and digest and
  retains its version, copyright, trademark and matching complete OFL text.
  [Reviewed fonts and additional rights holders](rw02-gui-dependencies.md).
- On Linux, the 101 original protocol XMLs include wayland-client's core
  `wayland.xml`. Its authenticated `src/lib.rs` invokes both generators.
  Every XML has an explicit `protocolGrants` record. The 30 XMLs with an
  SPDX tag point to the corresponding full original Plasma REUSE text. Raw
  grants point to the XML itself, and the historical fullscreen-shell input
  points to Weston's grant. All five Plasma REUSE texts and `COPYING.LIB`
  retain their original bytes. Windows selects none of these protocol packages.
- Every target includes the original SQLite `sqlite3/sqlite3.h` with its
  public-domain blessing. Each `source-notices/SHA256.txt` contains exact
  source bytes. In each package's `sourceAttributions`, the original relative
  path, full file SHA-256, byte offset and length identify every excerpt.
  Equal excerpts share one ZIP member. The selection includes source
  comments, data headers, copyright and license sections in documentation,
  source generators and conditional or test inputs of compiled packages.
  Examples include Adobe's original Glyph List header and its
  source reference in read-fonts, Sun's terms and FreeBSD origins in libm,
  and Unicode's ICU data attributions. [Attributed sources and extraction](../../tools/rust-qa/combined-profile/source_notices.py).
- For ring 0.17.14, `ringSourceInputs` identifies 361 original source,
  generator, assembler and preassembled inputs across its architectures.
  `ringTargetSelection` follows the authenticated `build.rs` source table
  for this target. It maps generated files back to their Perl sources,
  including the SHA-256 outputs generated by the SHA-512 scripts. The local
  source coverage includes the complete Google, Intel and Brian Smith ISC
  grants and the separate Andrew Moon public-domain credit in Poly1305.
  The build records 28 x64 and 22 ARM64 architecture candidates. The maps
  cover 12 ELF assembler sources on x64 Linux, 12 NASM sources and 12 COFF
  objects on Windows x64, and 11 assembler sources on each ARM64 target.
  The archive identifies possible input files and build roles. Object-level
  retention by the final installed executable requires separate evidence.
  [Original ring crate](https://static.crates.io/crates/ring/ring-0.17.14.crate).

## Offline generation and checks

The generator requires Python 3.11 or later, Git, the native revision in
the local repository, the original desktop assessment ZIP and the existing
project-local Cargo acquisition caches and the verified reconstructed GUI trees. It verifies the published digest of
the ZIP, the native evidence and compiler units, the immutable source review,
the original crate digest before reading its members, and each selected
member's digest. It selects files by their reviewed paths. The resulting ZIP
uses stored members, a fixed timestamp, ordering and file modes. It is made
visible using a hard link to the fully checked file in the same directory.
Repeating a build at the same destination verifies any existing bytes.
[Generator](../../tools/rust-qa/combined-profile/notices.py).

For example, run the following in the repository root for Linux x64.

```sh
revision=7517e3b6be84645bc0d40603750b003dd5792104
target=x86_64-unknown-linux-gnu
native_zip=artifacts/rust/hosted-desktop-storage/45047460092/linux-x64.zip
native_sha=afd05f889c75c40f2a1f3cebc9f413c9fc48c488160f1fa1f0f45bd68e0f8b6c
output_dir=artifacts/rust/combined-profile/qualified-notices-7517e3b

for copy in first repeat
do
    python3 -B tools/rust-qa/combined-profile/notices.py "$target" \
        --revision "$revision" --input "$native_zip" --archive-sha256 "$native_sha" \
        --output "$output_dir/$copy/linux-x64.zip" || exit 1
done
cmp "$output_dir/first/linux-x64.zip" "$output_dir/repeat/linux-x64.zip"
python3 -B tools/rust-qa/combined-profile/test_notices.py --target "$target" \
    --revision "$revision" --input "$native_zip" --archive-sha256 "$native_sha" \
    --notices "$output_dir/first/linux-x64.zip"
```

The optional `--source-inventory PATH` accepts a precomputed corrected
`inventory.json` with the exact canonical digest pinned above. The default
re-audits the historical inputs from the local original sources. A new
native run already carries the corrected inventory in its own receipt.

On 2026-11-22 two separate invocations produced identical bytes per target.
The readback checked the complete member list, original source digests and
ranges, file sizes, CRCs, ZIP metadata, package roles and font records. It
checked all Wayland assignments, the full Adobe and ring notices, generator
inputs, SQLite's blessing and granit-parser's relative links. Negative
controls rejected a missing Poly1305 credit in the supplemental inventory,
changed crate and excerpt bytes, invalid ranges, absent, duplicate or linked
members, an incomplete REUSE set, an altered ring build recipe and conflicting
destinations. [Readback and controls](../../tools/rust-qa/combined-profile/test_notices.py).

A separate reader compared the completed ZIPs directly to original crate
members, reconstructed compiler files and Git blobs. On Linux x64 it
matched 717 whole originals and 2,474 source-range references. Linux ARM64
matched 715 and 2,473, Windows x64 matched 463 and 2,384, and Windows ARM64
matched 461 and 2,383. Repeated references to the same original text account
for the higher range counts than the distinct block counts in the table.
